# How PhotoPrism does authentication

Historical research for [Geobook's owner-login spec](https://github.com/ahemberg/geobook/issues/86).
The upstream findings below describe the sources at the time of the investigation.
Geobook's decisions are recorded in [ADR 0003](../adr/0003-one-owner-signs-in-with-a-session-cookie.md)
and [ADR 0004](../adr/0004-spring-security-with-own-session-store.md). For current
configuration and recovery commands, use [deployment](../deployment.md).

Research for copying PhotoPrism's login system into geobook. Researched 2026-10-25.

Sources are PhotoPrism's Go source on the default branch, pinned to commit [`70e20b5`](https://github.com/photoprism/photoprism/tree/70e20b5e033f29e4d53b0eb34de44856806637d1) (2026-10-24), the docs at docs.photoprism.app, and the edition pages on photoprism.app.

The public repository holds the Community Edition. Plus and Pro add code that isn't public, so anything edition-specific comes from the docs.

## Admin bootstrap

- The built-in admin is a fixed record with `ID: 1`, `UserName: "admin"`, role `admin`, `SuperAdmin: true`, `CanLogin: true`, `WebDAV: true`, and the `local` auth provider. [auth_user_default.go#L18-L31](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user_default.go#L18-L31)
- `CreateDefaultUsers` loads the existing admin row if there is one. If not, it creates the row, carrying over values from a legacy user table if one exists. [auth_user_default.go#L63-L80](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user_default.go#L63-L80)
- `PHOTOPRISM_ADMIN_USER` (alias `PHOTOPRISM_ADMIN_USERNAME`, flag `--admin-user`) defaults to `admin`. A name with non-ASCII characters is ignored with a warning and `admin` is used. [flags.go#L55-L61](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/flags.go#L55-L61), [config_auth.go#L84-L102](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_auth.go#L84-L102)
- `PHOTOPRISM_ADMIN_PASSWORD` (flag `--admin-password`) has no default. If it is unset, the config looks for a password file through `FlagFilePath("ADMIN_PASSWORD")`. The value is trimmed of whitespace. [config_auth.go#L114-L129](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_auth.go#L114-L129)
- On every database migration at startup, `MigrateDb` calls `Admin.InitAccount(name, password, scope)` if a password is configured. If none is configured it logs "account cannot be initialized due to missing or invalid password". [config_db.go#L576-L581](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_db.go#L576-L581)
- `InitAccount` returns early if the account already has a row in the `passwords` table. Only when no password exists does it save the hash, rename the account to `PHOTOPRISM_ADMIN_USER`, and apply `PHOTOPRISM_ADMIN_SCOPE`. So changing either variable after the first start does nothing. [auth_user.go#L400-L445](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user.go#L400-L445)
- The docs say the same thing. "You cannot change the password with PHOTOPRISM_ADMIN_PASSWORD after the app has been started for the first time." Use `photoprism passwd [username]` instead. [docs: Docker Compose](https://docs.photoprism.app/getting-started/docker-compose/)
- `InitAccount` calls `NewPassword(uid, pw, allowHash=true)`, so the variable can hold a ready-made bcrypt hash. Such a hash is stored as-is. [password.go#L60-L66](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/password.go#L60-L66)
- Minimum length is the subject of an open question below. The docs and the flag help say 8 to 72 characters ([flags.go#L62-L67](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/flags.go#L62-L67), [docs: Docker Compose](https://docs.photoprism.app/getting-started/docker-compose/)). But I found no check against `PasswordLength` in the `InitAccount` path. `Password.SetPassword` rejects only empty passwords and passwords over 72 bytes. [password.go#L53-L58](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/password.go#L53-L58)

## Sessions

### Token generation and format

- A new session gets a random token from `rnd.AuthToken()`. It reads 24 bytes from `crypto/rand` and hex-encodes them, giving 48 lowercase hex characters. Example: `9fa8e562564dac91b96881040e98f6719212a1a364e0bb25`. [rnd/auth.go#L9-L42](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/rnd/auth.go#L9-L42), [rnd/random.go#L15](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/rnd/random.go#L15)
- Each session also gets a short public reference ID, `sess` plus 8 base36 characters. It appears in logs and lets admins delete sessions without seeing the token. [auth_session.go#L241-L255](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session.go#L241-L255), [rnd/ref_id.go#L4-L12](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/rnd/ref_id.go#L4-L12)

### Storage

- Sessions live in the `auth_sessions` table. The primary key `id` holds `SHA-256(token)` as 64 hex characters, not the token. The token itself is an unexported field tagged `gorm:"-"`, so it is never persisted. [auth_session.go#L57-L99](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session.go#L57-L99), [auth_session.go#L211-L234](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session.go#L211-L234), [rnd/auth.go#L198-L210](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/rnd/auth.go#L198-L210)
- Other columns that matter for a copy are `user_uid`, `user_name`, `client_uid`, `client_name`, `client_ip`, `auth_provider`, `auth_method`, `auth_scope`, `grant_type`, `last_active`, `sess_expires` (absolute Unix time, indexed), `sess_timeout` (seconds), `user_agent`, `data_json`, `ref_id`, `login_ip`, and `login_at`. [auth_session.go#L58-L94](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session.go#L58-L94)
- To look up a request, the server hashes the presented token and finds the row by `id`. A process-local cache holds sessions for `PHOTOPRISM_SESSION_CACHE` seconds (default 900, clamped to 60 to 3600). An expired session is deleted when someone looks it up. [api/session.go#L26-L65](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session.go#L26-L65), [auth_session_cache.go#L55-L96](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_cache.go#L55-L96), [config_auth.go#L224-L236](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_auth.go#L224-L236)
- Because of that cache, the docs warn that revocations made from the CLI take effect on a running instance only after up to 15 minutes. [docs: User Management Commands](https://docs.photoprism.app/user-guide/users/cli/)

### How the client sends the token

- The server reads `X-Auth-Token` first, then `X-Session-ID`, then `Authorization: Bearer <token>`. [header/auth.go#L13-L55](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/http/header/auth.go#L13-L55)
- The web UI sends `X-Auth-Token`. It keeps the token in `localStorage` under `session.token`, or in `sessionStorage` if the user picked that storage option. [session.js#L41](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/frontend/src/common/session.js#L41), [session.js#L96-L104](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/frontend/src/common/session.js#L96-L104), [api.js#L91](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/frontend/src/common/api.js#L91)
- No cookie carries the main session. The only session cookie is `oidc_session`, an HMAC-signed cookie with a 10-minute lifetime, scoped to `/api/v1/oauth`. It is set only on a cluster Portal acting as an OIDC provider. [oidc_session_cookie.go#L26-L35](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/oidc_session_cookie.go#L26-L35), [session_create.go#L163-L168](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_create.go#L163-L168)

### Login endpoint

- `POST /api/v1/session` (also `/api/v1/sessions`) takes JSON `{username, password, code, token}`. `code` is the 2FA passcode and `token` is a share-link token. [form/login.go#L8-L16](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/form/login.go#L8-L16), [session_create.go#L21-L176](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_create.go#L21-L176)
- The response holds `access_token` (the plaintext token), `session_id` (the SHA-256 ID), `token_type: "Bearer"`, `expires_in`, `provider`, `scope`, `user`, `data`, and `config`. A deprecated `id` field repeats the token. [session_response.go#L33-L63](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_response.go#L33-L63)
- If a registered session is already attached to the request, a password login calls `Regenerate()`. That deletes the old row and issues a new token, which prevents session fixation. [auth_session_login.go#L254-L258](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_login.go#L254-L258)
- An unknown user, a disabled login, and a wrong password all return the same `ErrInvalidCredentials` message. The audit log records the real reason. [auth_session_login.go#L88-L195](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_login.go#L88-L195)
- `GET /api/v1/session` returns the current session, and `DELETE /api/v1/session` logs out. [session_get.go#L83-L85](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_get.go#L83-L85), [session_delete.go#L121-L123](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_delete.go#L121-L123)

### Lifetime defaults

| Option | Flag | Default | Source |
|---|---|---|---|
| `PHOTOPRISM_SESSION_MAXAGE` | `--session-maxage` | 1209600 s (2 weeks) | [config_const.go#L102](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_const.go#L102) |
| `PHOTOPRISM_SESSION_TIMEOUT` | `--session-timeout` | 604800 s (1 week) | [config_const.go#L105](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_const.go#L105) |
| `PHOTOPRISM_SESSION_CACHE` | `--session-cache` | 900 s (15 min) | [config_const.go#L117](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_const.go#L117) |

- Setting max age or timeout to `-1` disables it, and `0` means the default. [config_auth.go#L201-L222](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_auth.go#L201-L222), [flags.go#L172-L189](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/flags.go#L172-L189)
- When the account has 2FA enabled, both values are doubled for non-client sessions. [session_create.go#L134-L138](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_create.go#L134-L138)
- The idle timeout is a gotcha. `Session.Expired()` checks the absolute expiry whenever `sess_expires > 0`, and falls back to `TimedOut()` only when the session has no expiry. With the defaults, which set both values, the code never enforces the one-week idle timeout. Only the two-week max age applies. The flag help in the source agrees, saying the timeout is "idle time in SECONDS for sessions without expiration". The docs config table describes the timeout as if it always applies. [auth_session.go#L1134-L1163](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session.go#L1134-L1163), [flags.go#L178-L183](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/flags.go#L178-L183), [docs: Config Options](https://docs.photoprism.app/getting-started/config-options/)
- `last_active` is written to the database when a session is loaded from the database. Cache hits update it in memory only. [auth_session_cache.go#L65-L83](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_cache.go#L65-L83)

### Logout and revocation

- Logout deletes the row and the cache entry. A caller with `sessions: manage` and `access_all` (admins) can delete another session by its ref ID. A regular user can delete only their own session. [session_delete.go#L36-L124](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_delete.go#L36-L124)
- A background worker deletes rows with `sess_expires > 0 AND sess_expires < now`. It runs at startup and then every 4 × session-cache (1 hour with defaults). [cleanup.go#L17-L46](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/session/cleanup.go#L17-L46), [start.go#L398](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/start.go#L398), [auth_session_delete.go#L149-L166](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_delete.go#L149-L166)
- Changing a password through the API, or activating 2FA, calls `RevokeDerivedSessions` for all other sessions of that user. That deletes regular logins and sessions created by logging in with an app password. App passwords and client tokens themselves are kept. [users_password.go#L119-L122](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/users_password.go#L119-L122), [users_passcode.go#L178-L181](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/users_passcode.go#L178-L181), [auth_user.go#L1200-L1235](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user.go#L1200-L1235)
- The docs add that deleting a user signs them out on all devices, including app passwords. [docs: Managing User Accounts](https://docs.photoprism.app/user-guide/users/)
- `photoprism auth rm [id]` deletes a single session. `photoprism auth reset --yes` clears `auth_sessions`, which forces everyone to log in again and also deletes app passwords. [auth_remove.go#L14-L17](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/auth_remove.go#L14-L17), [docs: User Management Commands](https://docs.photoprism.app/user-guide/users/cli/)

## Password hashing

- Passwords are hashed with bcrypt at cost 12 (`DefaultPasswordCost = 12`) using `golang.org/x/crypto/bcrypt`. [password.go#L14-L16](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/password.go#L14-L16), [password.go#L68-L74](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/password.go#L68-L74)
- Hashes live in a separate `passwords` table with columns `uid` (primary key), `hash`, `created_at`, and `updated_at`. `uid` is the user UID, or the client UID for OAuth2 client secrets, so one table holds both. [password.go#L18-L29](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/password.go#L18-L29), [auth_client.go#L763-L776](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_client.go#L763-L776)
- Passwords are trimmed of surrounding whitespace before hashing and before comparing. [clean/auth.go#L236-L238](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/clean/auth.go#L236-L238), [password.go#L82-L97](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/password.go#L82-L97)
- The minimum length is `PHOTOPRISM_PASSWORD_LENGTH`, default 8, counted in runes. It drops to 0 in public mode. [auth_user.go#L32-L39](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user.go#L32-L39), [config_auth.go#L139-L151](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_auth.go#L139-L151)
- The maximum is 72 bytes (`txt.ClipPassword`), which is bcrypt's input limit. [clip.go#L24-L25](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/txt/clip.go#L24-L25), [auth_user.go#L1280-L1289](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user.go#L1280-L1289)
- `User.SetPassword` validates the length, saves the hash, revokes connected OAuth app grants, and regenerates the user's preview and download tokens. [auth_user.go#L1258-L1278](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user.go#L1258-L1278)
- `PUT /api/v1/users/:uid/password` requires the old password. The exception is a super admin changing another account, who may leave it empty. A regular admin must know the target's current password. [users_password.go#L59-L100](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/users_password.go#L59-L100), [docs: Managing User Accounts](https://docs.photoprism.app/user-guide/users/)

## Roles and permissions

### Model

- The ACL is a map from Resource to Role to Grant, where a Grant is a map from Permission to bool. When a role has no entry for a resource, the `default` role entry applies. [acl/roles.go#L113-L125](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/roles.go#L113-L125), [acl/grant.go#L3-L4](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/grant.go#L3-L4)
- The role constants are `admin`, `manager`, `user`, `contributor`, `viewer`, `guest`, `visitor`, and `cluster_admin`, plus client roles `instance`, `service`, `portal`, and `client`. [acl/const.go#L9-L25](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/const.go#L9-L25)
- Community registers only `admin`, `guest`, `visitor`, and `none` as user roles. [acl/roles.go#L14-L21](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/roles.go#L14-L21)
- Permissions include `full_access`, `access_shared`, `access_library`, `access_private`, `access_own`, `access_all`, `use`, `search`, `view`, `upload`, `create`, `update`, `update_own`, `download`, `share`, `delete`, `rate`, `react`, `publish`, `subscribe`, `audit`, `manage`, and `manage_own`. [acl/const.go#L27-L52](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/const.go#L27-L52)
- Resources include `files`, `folders`, `shares`, `photos`, `videos`, `favorites`, `albums`, `calendar`, `moments`, `people`, `places`, `labels`, `cameras`, `lenses`, `config`, `settings`, `passcode`, `password`, `services`, `users`, `sessions`, `clients`, `logs`, `api`, `webdav`, `webhooks`, `metrics`, `vision`, `cluster`, `feedback`, and `mcp`. [acl/const.go#L54-L88](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/const.go#L54-L88)
- The rule table is one static Go map. For example, `password` grants `admin` full access and `guest` only `update_own`. `sessions` grants `admin` `manage_own` and every other role `own`. `clients` grants no role, because clients are managed only from the CLI. [acl/rules.go#L8-L115](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/rules.go#L8-L115)
- Grant bundles such as `GrantFullAccess`, `GrantOwn`, `GrantViewShared`, and `GrantDefaults` are defined in [acl/grant.go#L6-L165](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/grant.go#L6-L165).
- Each handler calls `Auth(c, resource, permission)`. For user sessions, that checks the user is known and enabled, then the session scope (if one is set), then `acl.Rules` for the user's role. For client sessions it checks the scope, the client role, and the owning user's role if there is one. [api_auth.go#L21-L193](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/api_auth.go#L21-L193)
- The `SuperAdmin` flag sits on the user row and is separate from the role. A super admin keeps admin rights even if their role is changed. [auth_user.go#L63](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user.go#L63), [docs: Roles and Permissions](https://docs.photoprism.app/user-guide/users/roles/)

### Editions

- Per the docs, "User and Viewer are available with Essentials and Plus; our Community Edition provides Admin, Guest, and Visitor." Pro adds roles for delegated administration and upload workflows. [docs: Roles and Permissions](https://docs.photoprism.app/user-guide/users/roles/)
- The Pro page lists Super Admin, Admin, Manager, User, Viewer, Contributor, and Guest. [photoprism.app/teams](https://www.photoprism.app/teams)

[auth_user_default.go#L48-L61](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user_default.go#L48-L61), [auth_session_login.go#L305-L312](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_login.go#L305-L312)

## App passwords and client credentials

All three credential types are rows in `auth_sessions`. App passwords and access tokens are long-lived sessions whose `id` is `SHA-256(secret)`.

### App passwords

- An app password is bound to a user. The format is 27 base62 characters split into four groups by `-`, and the last character is a checksum. Example: `OXiV72-wTtiL9-d04jO7-X7XP4p`. [rnd/auth.go#L53-L78](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/rnd/auth.go#L53-L78)
- The session row gets `auth_provider = "application"`. [auth_session_client.go#L9-L31](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_client.go#L9-L31)
- `photoprism auth add [username]` takes the flags `-n/--name CLIENT`, `-s/--scope SCOPE` (space-separated resources, or `*`), and `-e/--expires LIFETIME`. The lifetime defaults to one year (31536000 s), and `-1` means no limit. Without a username, the command creates a 48-hex client access token not bound to any user. [auth_add.go#L18-L123](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/auth_add.go#L18-L123), [docs: Client Credentials](https://docs.photoprism.app/user-guide/users/client-credentials/)
- In the UI (Settings > Account > Apps and Devices), the client calls `POST /api/v1/oauth/token` with `grant_type=password` and re-enters the account password. A missing 2FA code is accepted at that step. [oauth_token.go#L194-L248](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/oauth_token.go#L194-L248), [docs: 2FA](https://docs.photoprism.app/user-guide/users/2fa/)
- An app password can be used in two ways. It can be sent directly as a Bearer token. It can also go in the `password` field of `POST /api/v1/session`, which creates a child session with `auth_method = "session"`. That child session inherits the scope and is capped at the parent's expiry. [auth_session_login.go#L43-L169](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_login.go#L43-L169), [docs: Client Credentials](https://docs.photoprism.app/user-guide/users/client-credentials/)
- App password sessions are client sessions with role `client`. The `password` rule has no entry for `client`, and `users` gives it only `view_own`. So even with scope `*`, an app password can't change the password or manage users. [auth_session.go#L518-L551](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session.go#L518-L551), [acl/rules.go#L94-L106](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/rules.go#L94-L106), [docs: Client Credentials](https://docs.photoprism.app/user-guide/users/client-credentials/)
- A feature flag controls app passwords. When it is off, new app passwords can't be created and existing ones are rejected. [config_features.go#L39-L44](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/config/config_features.go#L39-L44), [api_auth.go#L108-L121](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/api_auth.go#L108-L121)

### OAuth2 client credentials

- A client is a row in `auth_clients` with a client UID, role, scope, `auth_expires` (token lifetime), `auth_tokens` (maximum active tokens), and `auth_enabled`. The client secret is 32 base62 characters, bcrypt-hashed into the `passwords` table. [auth_client.go#L43-L77](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_client.go#L43-L77), [rnd/client.go#L3-L20](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/rnd/client.go#L3-L20), [auth_client.go#L749-L810](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_client.go#L749-L810)
- `photoprism clients add|ls|show|mod|rm|reset` manages clients. Flags are `-n/--name`, `-r/--role` (default `client`), `-s/--scope`, `-e/--expires` (default 86400 s), `-t/--tokens` (default 10, `-1` for unlimited), `--redirect-uri`, `-p/--provider`, `-m/--method`, and `--secret`. `mod` also takes `--regenerate`. [clients.go#L44-L165](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/clients.go#L44-L165), [docs: Client Credentials](https://docs.photoprism.app/user-guide/users/client-credentials/)
- `POST /api/v1/oauth/token` with `grant_type=client_credentials` checks the client exists, is enabled, and has a valid secret. It then issues a session token that lives `auth_expires` seconds, and deletes the oldest tokens once the client has more than `auth_tokens`. [oauth_token.go#L158-L192](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/oauth_token.go#L158-L192), [oauth_token.go#L276-L281](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/oauth_token.go#L276-L281), [auth_client.go#L899-L913](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_client.go#L899-L913)
- The token response contains `access_token`, `token_type`, `expires_in`, `client_name`, `client_role`, and `scope`. [oauth_token.go#L284-L296](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/oauth_token.go#L284-L296)
- Clients can't log in to the web UI or use WebDAV. [docs: Client Credentials](https://docs.photoprism.app/user-guide/users/client-credentials/)

### Scopes

- A scope is a space-separated list of resource names. `*` allows everything, and the bare word `read` allows all read permissions on every resource. A resource list combined with `read` or `write` limits those resources to the read or write permission sets. [acl/scope.go#L10-L114](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/auth/acl/scope.go#L10-L114)
- `photoprism show scopes` lists the scopes a given build supports. [docs: Client Credentials](https://docs.photoprism.app/user-guide/users/client-credentials/)

## 2FA

- 2FA uses TOTP only, via `github.com/pquerna/otp` v1.5.0. The key comes from `totp.Generate` with the app name as issuer and the username as account name, plus library defaults. Those are SHA1, 6 digits, a 30-second period, and a 20-byte secret from `crypto/rand`. [rnd/auth_key.go#L10-L26](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/rnd/auth_key.go#L10-L26), [go.mod#L138](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/go.mod#L138), [pquerna/otp totp.go#L157-L200](https://github.com/pquerna/otp/blob/v1.5.0/totp/totp.go#L157-L200)
- Validation allows a skew of 1 step, so it accepts plus or minus 30 seconds. [passcode.go#L264-L277](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/passcode.go#L264-L277)
- Keys are stored in the `passcodes` table, with primary key (`uid`, `key_type`) and columns `key_url` (the full `otpauth://` URL, secret included), `recovery_code`, `verified_at`, and `activated_at`. The secret and the recovery code are stored in plaintext, not hashed. [passcode.go#L20-L36](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/passcode.go#L20-L36)
- There is one recovery code, 12 base36 characters. [rnd/auth_key.go#L28-L31](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/rnd/auth_key.go#L28-L31)
- The recovery code is compared in constant time. Using it logs the user in and turns off 2FA for the account. [passcode.go#L258-L262](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/passcode.go#L258-L262), [auth_user.go#L1384-L1401](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_user.go#L1384-L1401)
- Setup is a three-step API flow, and the user can manage only their own account. [users_passcode.go#L37-L311](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/users_passcode.go#L37-L311)
  1. `POST /api/v1/users/:uid/passcode` with the account password returns the secret, a 350 px QR code PNG as a data URL, and the recovery code. [passcode_json.go#L10-L33](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/passcode_json.go#L10-L33)
  2. `POST .../passcode/confirm` with a valid code sets `verified_at`.
  3. `POST .../passcode/activate` sets `activated_at`, sets `auth_method = "2fa"` on the user, and revokes the user's other sessions.
  4. `POST .../passcode/deactivate` with the password deletes the key.
- Login with 2FA works in two round trips. If the password is right but `code` is missing, the server answers 401 with message code 32 ("passcode required") and refunds the rate-limit tokens, so the UI can ask for the code. [session_create.go#L110-L125](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_create.go#L110-L125), [auth_session_login.go#L199-L228](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_login.go#L199-L228)
- An admin can turn off 2FA from the CLI with `photoprism users mod --disable-2fa [username]`. [users_mod.go#L17-L23](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users_mod.go#L17-L23), [docs: 2FA](https://docs.photoprism.app/user-guide/users/2fa/)
- Users switch to a new authenticator by deactivating 2FA and enabling it again. [docs: 2FA](https://docs.photoprism.app/user-guide/users/2fa/)
- The edition table marks "Login with 2FA" as included in Community, Essentials, and Plus. [photoprism.app/editions](https://www.photoprism.app/editions)

## Rate limiting and brute-force protection

- Rate limiting uses per-IP token buckets from `golang.org/x/time/rate`. IPv4 addresses are bucketed one per address and IPv6 per /64. A request with no usable IP falls into the `0.0.0.0` bucket. [limit.go#L16-L75](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/server/limiter/limit.go#L16-L75), [ip.go#L89](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/http/header/ip.go#L89), [ip.go#L108-L133](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/pkg/http/header/ip.go#L108-L133)
- `limiter.Login` covers password and 2FA attempts. The burst is 10 and it refills 1 token per minute. [login.go#L9-L16](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/server/limiter/login.go#L9-L16)
- Every attempt reserves a token. A login with a 2FA code reserves 3, which is why the minimum burst is 3. [session_create.go#L82-L94](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session_create.go#L82-L94), [limit.go#L26-L46](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/server/limiter/limit.go#L26-L46)
- A successful login refunds the reserved tokens with `r.Success()`, so only failed attempts count against the limit. [request.go#L44-L50](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/server/limiter/request.go#L44-L50)
- The same limiter guards password change, 2FA setup, confirm, and deactivate, and the OAuth token endpoint. [users_password.go#L51-L57](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/users_password.go#L51-L57), [users_passcode.go#L49-L55](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/users_passcode.go#L49-L55), [oauth_token.go#L141-L145](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/oauth_token.go#L141-L145)
- `limiter.Auth` covers invalid bearer tokens. The burst is 60 and it refills 1 token per 10 seconds. A well-formed token that matches no session costs one token. Once the bucket is empty, every authenticated endpoint returns 429 for that IP. [auth.go#L9-L16](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/server/limiter/auth.go#L9-L16), [api/session.go#L39-L61](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/session.go#L39-L61), [api_auth.go#L56-L59](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/api/api_auth.go#L56-L59)
- A rejected request gets HTTP 429 with `{"error":"rate limit exceeded","code":429}`. [abort.go#L14-L17](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/server/limiter/abort.go#L14-L17)
- The code has no per-account lockout. The limits apply per IP or network only.
- Every login attempt is written to an audit log, which `photoprism audit logins [username]` displays. The docs say this log isn't available in the web UI. [auth_session_login.go#L93-L94](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/entity/auth_session_login.go#L93-L94), [docs: User Management Commands](https://docs.photoprism.app/user-guide/users/cli/)
- In Community, these limits are compile-time constants. The edition table lists "Custom Rate Limits" for Plus only. [photoprism.app/editions](https://www.photoprism.app/editions)

- LDAP is documented only in the Pro knowledge base, with `PHOTOPRISM_LDAP_URI` and related options. [photoprism.app/pro/kb/ldap](https://www.photoprism.app/pro/kb/ldap)
- Some `users add/mod` flags are edition-only. `--upload-path` needs Plus or Pro. `--scope`, `--attr`, and `--base-path` need Pro. [docs: User Management Commands](https://docs.photoprism.app/user-guide/users/cli/)

## CLI commands for user management

The commands come from [users.go#L51-L117](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users.go#L51-L117) and the [User Management Commands docs](https://docs.photoprism.app/user-guide/users/cli/).

- `photoprism users ls [search]` lists accounts. Flags are `-n/--count` (default 100), `-l/--login` (show last login), `-a/--created`, `-r/--deleted`, and the report format flags (`--md`, `--csv`, `--tsv`). [users_list.go#L16-L18](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users_list.go#L16-L18), [users.go#L120-L144](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users.go#L120-L144), [commands.go#L184-L189](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/commands.go#L184-L189)
- `photoprism users add [username]` creates an account. It takes the shared user flags plus `--restore`, which restores a deleted account with the same name without asking. [users_add.go#L20-L23](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users_add.go#L20-L23)
- The shared user flags for `add` and `mod` are:
  - `-n/--name NAME` for the display name
  - `-m/--email EMAIL`
  - `-p/--password PASSWORD` (8 to 72 characters, prompted if omitted on `add`)
  - `-r/--role ROLE` (default `admin`)
  - `-A/--auth PROVIDER` (`default`, `local`, `oidc`, or `none`)
  - `--auth-id ID`
  - `--auth-issuer URL`
  - `--superadmin` (alias `--super`)
  - `-l/--no-login`
  - `-w/--webdav`
  - `--mcp`

  Sources: [users.go#L12-L26](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users.go#L12-L26), [users.go#L66-L117](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users.go#L66-L117), [flags.go#L64](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/flags.go#L64)
- `photoprism users mod [username]` takes the same flags plus `--disable-2fa`. [users_mod.go#L17-L23](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users_mod.go#L17-L23)
- `photoprism users show [username]` prints the account details, with the report format flags. [users_show.go#L17-L20](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users_show.go#L17-L20)
- `photoprism users rm [username]` deletes the account. `-y/--yes` skips the confirmation prompt, and `--force` is kept as a deprecated flag. Per the docs, deletion signs the account out everywhere and keeps the row as soft-deleted. [users_remove.go#L16-L23](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users_remove.go#L16-L23), [docs: Managing User Accounts](https://docs.photoprism.app/user-guide/users/)
- `photoprism users reset --yes` drops and recreates the user tables. It removes all accounts, sessions, app passwords, 2FA keys, shares, and the clients owned by users. `-t/--trace` adds trace logging. [users_reset.go#L18-L40](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/users_reset.go#L18-L40)
- `photoprism users legacy [search]` lists accounts left in the pre-2022 legacy table. [docs: User Management Commands](https://docs.photoprism.app/user-guide/users/cli/)
- `photoprism passwd [username]` prompts twice for a new password and checks the min and max length. `-s/--show` prints the resulting bcrypt hash, and `--rm/--remove` deletes the local password. [passwd.go#L23-L112](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/passwd.go#L23-L112)
- The session commands are `photoprism auth ls|add|show|rm|reset` (alias `sess`). [auth.go#L18-L20](https://github.com/photoprism/photoprism/blob/70e20b5e033f29e4d53b0eb34de44856806637d1/internal/commands/auth.go#L18-L20)

## Open questions

- I couldn't confirm the minimum admin bootstrap password length. The docs say 8, and the troubleshooting page says a shorter `PHOTOPRISM_ADMIN_PASSWORD` starts the app with no password. But `InitAccount` and `Password.SetPassword` only reject empty or over-72-byte values, and I found no length check on that path in this commit.
- The docs say the idle timeout applies to all sessions. My reading of `Session.Expired()` is that it applies only to sessions without a max age. I didn't run it to confirm.
- The troubleshooting docs mention `PHOTOPRISM_LOGIN_LIMIT`, but no such option exists in the Community source. It may be the Plus "Custom Rate Limits" feature, which I can't see.
- The ACL grants for the Plus and Pro roles (user, viewer, manager, contributor) are in code that isn't public. The docs describe them only in prose, as a capability table with columns for search, view, upload, WebDAV, and manage.
- "Hardened Security" (Plus) and "Intrusion Prevention" (Pro) aren't defined in any source I read.
- I didn't find session revocation in the CLI `passwd` path. It calls `User.SetPassword`, which revokes OAuth app grants and regenerates preview and download tokens. Only the API handler calls `RevokeDerivedSessions`. The docs say "When a password or privilege level changes, PhotoPrism invalidates that user's other active sessions," which may describe the web UI path only.
- The editions comparison table has no stable anchor or version. The table above is a snapshot from 2026-10-25.
